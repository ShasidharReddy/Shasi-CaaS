Linux Administration Guide

Use this document as a day-one through day-two operations reference for provisioning, hardening, patching, and troubleshooting Linux systems that support production application platforms.

Audience

Platform engineers, SREs, and cloud administrators supporting Linux workloads.

Focus

Secure defaults, lifecycle automation, and operational discipline.

Core tooling

systemd, journald, ssh, sudo, package managers, and shell automation.

Operational Baseline

  • Standardize host naming, timezone, package mirrors, and log forwarding from the first bootstrap action.
  • Use configuration management to enforce users, SSH policy, packages, services, and audit configuration.
  • Keep immutable infrastructure principles for stateless services and documented break-glass steps for mutable hosts.

Provisioning Checklist

Access

Disable password login, use short-lived keys, and limit sudo through role-based groups.

Packages

Patch immediately, remove unused services, and pin critical repositories for predictable updates.

Storage

Align filesystem layout with application write patterns and reserve space for logs and temp data.

Monitoring

Install node exporters, forward logs, and validate alert coverage before handoff.

Service Management

Every production service should ship with a tested systemd unit, clear restart policy, and structured log output. Use service dependencies to protect startup order and isolate secrets through environment files or external secret stores.

AreaWhat to enforceWhy it matters
systemdRestart=on-failure, health probes, resource limitsReduces manual intervention and runaway processes.
journaldPersistent storage with retention controlsPreserves evidence for incidents and audits.
cron / timersIdempotent jobs with alerting on failuresPrevents silent backup or cleanup drift.

Security Hardening

  1. Enable host firewalls with explicit allow rules per environment.
  2. Collect audit events for privilege escalation, SSH changes, and package mutations.
  3. Rotate secrets, validate TLS trust stores, and document certificate renewal paths.
  4. Apply CIS-inspired controls pragmatically to avoid breaking required service behavior.

Incident Response Notes

During incidents, gather process state, open sockets, recent package changes, disk pressure, and recent auth events before rebooting a node. Reboots can erase the highest-value clues unless logs and metrics are already centralized.
